## Scene tree
```
TT92                       root (Node3D)
├─ Body                    static, material M_TT92_Body
├─ Mechanical              static, material M_TT92_Mech (engine, exhaust, afterburner, suspension)
├─ SteeringWheel           pivot on the wheel centre
├─ Wheel_FL / Wheel_FR     pivot on the axle, material M_TT92_Mech
├─ Wheel_RL / Wheel_RR
└─ Body_00-convcolonly     convex hull -> Godot turns it into a collision shape and hides the mesh
```
Units: metres, scale 1. Up = +Y. The car's nose points to **+Z** after import (glTF front), i.e. the
opposite of Godot's -Z "forward": rotate the root 180° about Y, or use `use_model_front = true`
where an API offers it. Wheels spin about their local X axis.

## Import
1. Copy this whole folder into the project as `res://VEH_TT92_Racing_Car/` (the `.tres` files expect
   that path; if you use another folder, fix the `path=` lines at the top of each `.tres`).
2. **GLB**: just drop it in. Godot builds `StandardMaterial3D` materials from the embedded textures
   (albedo, ORM channels, normal, emission) on its own.
3. To use the ready-made materials instead: select the `.glb` → *Import* dock → *Advanced…* →
   *Materials* → for `M_TT92_Body` / `M_TT92_Mech` enable *Use External* and pick
   `M_TT92_<Set>_ORM.tres` **or** `M_TT92_<Set>_Standard.tres`. Both look the same:
   ORM = one texture fetch instead of three (use this in the game),
   Standard = separate maps (easier to tweak one channel).
4. Normal maps: Godot detects them and imports them as RG-compressed normal maps. If one looks
   wrong, check *Import → Compress → Normal Map = Enable* on the `_Normal.png`.
5. Collision: `Body_00-convcolonly` becomes a `StaticBody3D` + convex `CollisionShape3D`. For a
   drivable `VehicleBody3D` move that shape under your vehicle body and add four `VehicleWheel3D`
   nodes at the `Wheel_*` positions.
6. LODs: none are shipped. Godot generates mesh LODs and shadow meshes at import
   (*Meshes → Generate LODs*, on by default).

## FBX note
FBX has no packed-ORM concept and Blender's FBX exporter only writes base colour, normal and
emission texture links. After importing the `.fbx`, assign one of the `.tres` materials (step 3) to
get roughness / metallic / AO. Exported with *FBX Units Scale* (1 unit = 1 m, no 100× scale),
-Z forward, Y up, tangents included. Godot reads FBX natively through `ufbx` since 4.3.

## How the textures were made
The Blender look uses one procedural master material (tri-planar projection, clear coat, dirt,
edge wear). Engines cannot read that, so every channel was **baked** with Cycles onto a
non-overlapping 0–1 UV atlas per set:
- base colour, roughness, metallic, emission: emission bakes of the material inputs (lighting-free)
- normal: tangent-space bake of the normal map + bump detail
- AO: ray-traced ambient occlusion between all parts
The clear coat of the paint cannot be exported; 75 % of it is folded into the baked roughness. For
the full effect set *Clearcoat* on the Body material in Godot (≈ 0.6, roughness ≈ 0.1).

## Limits (honest list)
- Tested in Godot 4.7.2 (Forward+, d3d12): GLB and FBX import, 7 meshes / 80,736 triangles, 1 collision
  shape, both materials with albedo + normal + roughness + metallic + AO (+ emission x6 on Mech),
  back-face culling on. The `.tres` materials were not assigned in that test (the GLB's own were used).
- UVs are an automatic atlas (smart project + pack): fine for baked textures, not laid out for
  hand painting.
- One material per texture set covers many surface types; sheen (cloth, leather) and anisotropy
  (brushed steel) of the Blender materials are not represented.
- The helical heat-wrap strands of the Blender model are not in the game mesh (9.6k triangles and
  metre-long UV strips); the wrap core underneath carries the baked wrap texture.
- Tyres have no tread pattern.
